### Phase 3: The Double Ratchet Protocol
- [x] Implement DH Ratchet (asymmetric step advancing root key).
- [x] Implement Symmetric KDF Chains (sending and receiving message chains).
- [x] Implement out-of-order skipped message key storage with expiration TTL.
- [x] Implement ratchet session state serialization and persistence in IndexedDB.

### Phase 4: Sealed Sender & Metadata Blinding
- [x] Implement Delivery Tokens generated by recipients for authorized relay routing.
- [x] Implement server Ed25519 root authority and short-lived sender certificates.
- [x] Strip sender identity (`from`) from outer transit envelope.
- [x] Build SQLite database on server for persistent prekey storage and atomic OPK claiming.

- [x] Implement Node.js WebSocket relay with in-memory FIFO queue (max 50, 1h TTL).
- [x] Implement token-bucket rate limiter (30 conn/min, 100 msg/min per IP).
- [x] Enforce sender identity verification on all WebSocket signaling frames.
- [x] Configure strict CSP, CORS, and security headers.

### Phase 6: Mobile Hardening (Capacitor Android)
- [x] Configure Capacitor bridge for Android with native asset packaging.
- [x] Implement `FLAG_SECURE` in Android activity to block OS screenshots and task switcher previews.
- [x] Integrate native Android BiometricPrompt / Fingerprint authentication.
- [x] Store vault master keys in Android Keystore / EncryptedSharedPreferences via secure storage plugin.

### Phase 7: Comprehensive Security Audit Remediation
- [x] Implement AES-256-GCM data-at-rest encryption for IndexedDB message storage.

- [x] Enforce zeroization of ephemeral memory buffers and attachment blob URLs.

### Phase 8: Dual-Mode Architecture (Veil Flow & Veil Bunker)
- [x] Implement seamless Dual-Mode toggle between *Veil Flow* (WhatsApp style) and *Veil Bunker* (Tactical HUD).
